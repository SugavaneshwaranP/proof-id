2. ROOT CAUSE ANALYSIS: WHY "EVERYTHING LAGS"
================================================================================

[LAG BOTTLENECK #1] MONOLITHIC BUNDLE & ZERO CODE-SPLITTING
- Problem:
  In `app/src/App.jsx`, all 35 pages (HomePage, 6 Onboarding pages, 10 Dashboard
  pages, Public Profile pages, Admin Reports, etc.) were imported statically at the
  top of the file.
- Impact:
  Vite generated a single minified bundle:
  `dist/assets/index-OHMU1Af5.js: 943.29 kB (238.38 kB gzip)`
  Every visitor, whether loading the landing page or a public profile, had to download,
  parse, compile, and evaluate nearly 1MB of JavaScript. On average mobile devices,
  main-thread blocking time exceeded 1.8 seconds before First Input Delay (FID).
- Fix:
  Convert all page imports in `App.jsx` to `React.lazy()` with a central `Suspense`
  boundary and minimal skeleton fallbacks. Initial payload drops from 943 kB
  to ~120 kB (<80% reduction).

[LAG BOTTLENECK #2] GLOBAL SYNC EVENT BROADCAST STORMS
- Problem:
  In `app/src/lib/dbStore.js`, every cache read or update triggered:
  `window.dispatchEvent(new CustomEvent("backed-db-sync", { detail: memoryCache }));`
- Impact:
  Every active component listening via `dbStore.onSync(load)` re-evaluated its entire
  state, regardless of whether its specific slice changed. When a page triggered
  multiple parallel fetches (e.g. Profile + Evidence + Projects + Products),
  `backed-db-sync` fired 4 to 6 times in under 50ms, triggering cascading layout
  recalculations and UI stutter.
- Fix:
  Add debounce / microtask batching to `triggerSync()` using `requestAnimationFrame`.

[LAG BOTTLENECK #3] NETWORK WATERFALLS ON PUBLIC PROFILES
- Problem:
  In `PublicPersonProfilePage.jsx` and `PublicBusinessProfilePage.jsx`:
  On mount, four separate functions run in sequence/parallel:
  1. `dbStore.getProfile(slug)`
  2. `dbStore.getEvidence(slug)`
  3. `dbStore.getProjects(slug)` / `dbStore.getProducts(slug)`
  4. `dbStore.trackView(slug)`
- Impact:
  Sends 4 separate HTTP roundtrips to Supabase REST endpoints.
- Fix:
  Consolidate public profile read into a single composite query or RPC:
  `supabase.rpc('get_public_profile_bundle', { p_slug: slug })` returning
  profile, capabilities, projects, products, and verified evidence in 1 single roundtrip.

[LAG BOTTLENECK #4] REALTIME STATUS BAR DEV OVERHEAD IN APP SHELL
- Problem:
  `RealtimeStatusBar.jsx` was hard-coded at line 238 in `App.jsx`. It listened to
  all window realtime events, maintained state, and rendered simulated event buttons
  on every screen, including public and mobile views.
- Impact:
  Unnecessary DOM operations, event listeners, and visual noise.
- Fix:
  Hide `RealtimeStatusBar` unless `import.meta.env.DEV` is true.

[LAG BOTTLENECK #5] DUPLICATE INDEXEDDB DATABASES
- Problem:
  The codebase had two competing IndexedDB implementations:
  1. `app/src/lib/offlineQueue.js` (Database: `backed_offline_v1`)
  2. `app/src/lib/storage/indexedDB.js` (Database: `BackedDB`)
- Impact:
  Duplicate database connection pools, memory overhead, and uncoordinated stores.
- Fix:
  Unify into a single singleton IndexedDB provider.

[LAG BOTTLENECK #6] ANIMATION OVERHEAD ON LOWER-END GPUS
- Problem:
  Framer Motion animations (`initial={{ opacity: 0, y: 15 }}`, `animate`, `transition`)
  are attached to virtually every list item, badge, pill, and container.
- Impact:
  On mobile devices without hardware acceleration, Framer Motion forces composite
  re-draws and drops frame rates below 30 FPS.
- Fix:
  Add `reduced-motion` CSS checks and use pure CSS transitions for list items.

3. FEATURE LACKS & GAPS (SPECIFICATION VS. CURRENT IMPLEMENTATION)
================================================================================

1. OFFLINE QUEUE DRAIN WORKER (HIGH PRIORITY)
   - Status: Enqueue logic exists in `offlineQueue.js`, but no listener handled
     `window.addEventListener("online", flushPendingMutations)`.
   - Consequence: Offline mutations sat in IndexedDB indefinitely unless explicitly
     triggered.

2. EMAIL CONFIRMATION INTERSTITIAL (HIGH PRIORITY)
   - Status: Supabase Auth has email confirmations enabled. When a new user signs up
     in `SignUpPage.jsx`, their session is initially null.
   - Consequence: If they proceed directly into onboarding without confirming email,
     they cannot execute authenticated mutations.
   - Requirement: Add explicit "Check your inbox to verify your email" screen
     with resend option.

3. ADVANCED SEARCH & DISCOVERY FILTERS (MEDIUM PRIORITY)
   - Status: `DiscoverPage.jsx` filters by text search and Person/Business type.
   - Missing: Location dropdown, Availability Status toggle ("Open to work",
     "Advisory", "Not available"), and Verified Proof Count range filter
     (specified in `docs/PRODUCT.md` section 3).

4. B2B STRUCTURED QUOTE RESPONSE (MEDIUM PRIORITY)
   - Status: Buyers can transmit structured RFQs with quantity, lead time, and certs.
     Suppliers see them in `DashboardInboxPage.jsx`.
   - Missing: Suppliers can only change status to "responding". They cannot submit a
     structured quotation reply with pricing breakdown and validity date back
     to the buyer.

5. CLIENT-SIDE IMAGE COMPRESSION (MEDIUM PRIORITY)
   - Status: `DashboardEvidencePage.jsx` uploads files directly to `generate-upload-url`
     and Supabase Storage `evidence-vault`.
   - Missing: Automatic client-side canvas/WebP compression for large image files
     (>5 MB) to save bandwidth and stay within free-tier storage limits.

6. QR CODE & DEDICATED PDF EXPORT (LOW/POLISH)
   - Status: Basic `window.print()` triggers standard browser print dialog.
   - Missing: Dedicated `@media print` print-stylesheet and SVG QR code generator
     for physical badge sharing.

================================================================================
